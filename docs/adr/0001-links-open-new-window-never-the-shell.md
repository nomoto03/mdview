# ドキュメント参照は新しいウィンドウで開き、OSのシェルには渡さない

mdviewはこれまでリンクを一切ハンドルしておらず、リンクを踏むとWebViewごと外部サイトへ
遷移したり、存在しないURLへ飛んで白画面になったりしていた。これを塞ぐにあたり、
「1ウィンドウ = 1ドキュメント、対象は不変」という既存の性質を壊さないことを優先し、
ドキュメント参照は**同じウィンドウで遷移させず、新しいmdviewウィンドウで開く**ことにした。
これにより履歴・戻る操作・監視対象の張り替え・タイトル更新がすべて不要になる。

また、ローカルパスは**拡張子で分岐せず、常にmdview自身に渡す**。OSの既定アプリには
決して委ねない。Markdownの中身がリンクのクリックだけで任意のプログラムを起動できる
経路（`[手順](./setup.exe)`）を作らないためで、この規則がある限り、リンク経由で
起動され得るプロセスはmdviewだけになる。代償として、画像やPDFへのリンクを踏むと
mdviewが開いて読めない旨を表示する。

## Considered Options

- **同じウィンドウで遷移し `Alt+←` で戻る** — 読み物としては自然だが、履歴スタック、
  監視対象の張り替え、履歴エントリごとのスクロール位置が必要になり、実質ミニブラウザに
  なる。「ワークスペース機能なし」という方針に反する。
- **`.md`以外はOSの既定アプリで開く** — 画像やPDFが素直に開いて便利だが、信頼していない
  Markdownを開いたときに1クリックで実行ファイルが動く経路ができる。実行ファイルの
  除外リストで塞ぐ方式は、防御としてもれが出やすい。
