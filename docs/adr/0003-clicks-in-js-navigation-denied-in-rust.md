# リンクのクリックはJSで扱い、それ以外の遷移はRustで一律に拒否する

ドキュメント参照と外部リンクの処理をどこに置くかで、役割を2つに分けた。JS側の
clickハンドラがリンクのクリックだけを扱い、Rust側のnavigation handlerは自分の
オリジン以外への遷移を無条件・無言で拒否する。一見すると遮断点が2ヶ所に分かれて
冗長に見えるが、これは意図的なものである。

**理由は、navigation handlerがユーザー操作かどうかを区別できないこと。** 受け取るのは
URLだけで、「人がリンクを押した」のか「`<meta http-equiv="refresh">` で勝手に飛ばされた」
のかを知る手段がない。Rust側だけで全部さばく設計にすると、meta refreshを仕込んだ
ドキュメントを開いただけで、ユーザーが何もしていないのに既定ブラウザが起動してしまう。
clickイベントは「人が押した」という事実そのものなので、行動を起こしてよい条件を
そこに固定した。

この分担により、`<meta http-equiv="refresh">` と `<form action="https://...">` は
どちらも「何も起きない」に落ちる。両方ともCSPでは塞げない経路である
（`form-action` は `default-src` にフォールバックせず、meta refreshはCSPの管轄外）。

## Consequences

- `<a href>` はHTML生成時にRust側で絶対パスへ解決しておく必要がある。WebViewがURLへ
  解決した後では `../index.md` と `./index.md` がどちらも `/index.md` に正規化されて
  潰れてしまい、元の相対パスを復元できない。アセットの `<img src>` と同じ扱いになる。
- `#anchor` は同一オリジンのままなのでRust側の規則を素通りする。
