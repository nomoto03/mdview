# mdviewは状態を持たない

mdviewには設定ファイルがなく、ウィンドウの大きさも位置も履歴も記憶しない。これは
未実装ではなく、意図的な境界である。ウィンドウは常に既定の大きさで開き、プロセス間で
共有される状態はひとつもない。

**ウィンドウサイズ・位置の記憶を退けたのは、マルチインスタンスと相性が悪いため。**
mdviewは起動のたびに新しいプロセスが立つ設計なので、記憶を持たせると複数のプロセスが
同じ設定ファイルへ同時に書き込むことになる。3つ開いていたウィンドウをまとめて閉じれば
3つの書き手が競合する。この競合を設計して保守するコストは、毎回同じ大きさで開くことの
不便さに見合わない。

**ドラッグ＆ドロップを退けたのは、2つの理由から。** 落とされたウィンドウがドキュメントを
差し替える実装にすると、「1ウィンドウ = 1ドキュメント、対象は不変」という前提が崩れ、
監視対象の張り替えとタイトル更新が必要になる（ADR-0001で退けたものがそのまま戻ってくる）。
新しいウィンドウを開く実装にすれば前提は守れるが、「Aに落としたのにBが出てくる」という
挙動になるうえ、エクスプローラーの右クリック連携が既に同じ役割を果たしている。

## Consequences

- 設定項目を増やしたくなったとき、置き場所がない。追加するならこの決定を覆すところから
  始める必要がある。
- ウィンドウの既定サイズを変えたい場合は `tauri.conf.json` を編集して再ビルドする。
